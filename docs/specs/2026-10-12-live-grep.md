# Live grep: search as you type, and path globs

Status: implemented
Date: 2026-10-12

## Purpose

Two commands that search a project or a directory while the pattern is
typed in the minibuffer and show the hits as candidates, in the manner
of Doom's `+default/search-project` and `+default/search-cwd`. Today
those run one `rg` process per input through consult. Here the grep
service answers each input, the search for the previous input is
cancelled, and one key turns the live search into a `*quarry-grep*`
buffer with all its filters.

Success: the two commands can take the place of the Doom commands in
the author's daily use, including file type and glob limits typed after
` -- `; preview, grouping, `embark-export` and Doom's `C-c C-e` behave
as they do for `consult-ripgrep`.

## Scope

In:

- `quarry-consult-grep` and `quarry-consult-grep-project`, in a new file
  `lisp/quarry-consult-grep.el`. They need consult.
- The input syntax of ADR 0019: terms, `!` terms, options after ` -- `.
- The hand-over of a live search to the result buffer.
- Path globs in the service (ADR 0017): `/`, `**` and `!` in `:globs`,
  and a file type together with globs. The result buffer's file
  restriction (`f`, the FILES argument of the commands) gains the same.

Out:

- Key bindings and remaps. The package binds nothing; the README shows
  the lines for Doom.
- A front end without consult (plain `completing-read`).
- Context lines in the live search. The result buffer has them.
- An embark exporter of quarry's own: `embark-export` gives a
  `grep-mode` buffer, as for `consult-ripgrep` (ADR 0018).
- rg options outside the set below, and clusters of short options
  (`-Fi`).
- Remote directories: refused, as by the other grep commands.
- Searching on the file index (grep backlog); a live search walks the
  tree once per input.

## Design

### Path globs in the service

ADR 0017. In `src/grep/service.rs` and `src/grep/search.rs`:

- `:globs` is a list of gitignore-style globs relative to `:dir`. A glob
  without `/` matches a name at any depth; a glob with a `/` at its start or inside matches a
  path below `:dir`; `**` crosses directories; `!` in front excludes;
  the last glob that matches decides.
- They are compiled into an `ignore::overrides::Override` rooted at
  `:dir` and asked in the search's entry filter, together with the path
  filters, after the walker's own rules. A file is dropped when the
  matcher says "ignore": an excluding glob matched it, or there are
  including globs and none matched. A directory is not entered when an
  excluding glob matches it.
- `:file-type` and `:globs` may both be given; a file must pass both.
  `:file-type` alone works as before, through the walker's types.
- Errors, checked in `handle` before the search: an empty glob
  (`invalid glob "": it is empty`), a glob the matcher refuses
  (`invalid glob "GLOB": MESSAGE`). The errors "give a file type or
  globs, not both" and "glob ... names a directory" no longer exist.
- The module docs of `service.rs` and the type built from globs
  (`GLOB_TYPE`) are changed to match.

### The file restriction in Elisp

The slot `files` of `quarry-grep--search` is replaced by two: `type`
(nil or the name of a file type) and `globs` (a list of strings). The
request has `:file-type` and `:globs` as the value gives them, either,
both or neither.

Where words are read without saying which is which, one rule decides
(`quarry-grep--classify-files`, which needs `(:types)`): each word that
is a name from `(:types)` is the file type, every other word is a glob.
More than one type name is a `user-error` ("Give one file type; TYPES
are all types"). The rule is used by `quarry-grep--parse-files` (the
files prompt and `f`) and for the FILES argument of the commands, which
stays nil, a string or a list of strings. The live parser does not use
it: `-t` and `-g` say which is which, so it needs no type list, an
unknown `-t` name reaches the service and is its error, and two `-t`
are the parser's error.

- `f` and the files prompt accept, for example, `rust !gen/** src/**`.
  The prompt reads "Search in files (a type and globs)".
  `quarry-grep--files-text` shows the type and the globs in that form.
- In the prompt a glob that is spelled like a type name is taken as the
  type. To mean the glob, write it so that it is not the name
  (`[m]ake`).
- `quarry-grep--start` is split: `quarry-grep--start-search` takes a
  search value, makes or reuses the result buffer and runs it;
  `quarry-grep--start` builds the value and calls it. The hand-over
  below uses the first.

### Input syntax

ADR 0019. One pure function, `quarry-consult-grep--parse` (DIR INPUT),
returns a `quarry-grep--search`, or nil when there is nothing to search
yet, or signals a `user-error` whose message is shown in the prompt. It
needs neither consult nor the module.

INPUT is the search part that consult's split step hands on (with the
default style: the text between the first and the second `#`).

1. INPUT is cut at the first ` -- `: one or more spaces, `--`, then a
   space or the end. Left are the terms, right the options. A `--` at
   the very start counts too (options without terms: nothing to search).
2. Both halves are split into words at spaces that have no backslash in
   front. `\ ` in a word becomes a space. No other backslash is touched.
3. Terms:
   - A term that starts with `!` is an exclude line filter for the rest.
     A lone `!` is ignored: it is being typed. So is a backslash that
     ends the input unpaired.
   - A term that starts with `\!` is an include term that starts with
     `!`; the backslash is removed.
   - The include terms become include line filters in their order; the
     first is the primary filter.
   - No include term: the result is nil.
4. Options. A value is the next word, or attached (`-trust`,
   `--type=rust`).

   | Option | Meaning |
   |---|---|
   | `-t TYPE`, `--type TYPE` | file type; at most one |
   | `-g GLOB`, `--glob GLOB` | a glob, see above; any number, in order |
   | `-F`, `--fixed-strings` | all terms are literals, not regexps |
   | `-i`, `--ignore-case` | case rule `insensitive` |
   | `-s`, `--case-sensitive` | case rule `sensitive` |
   | `-S`, `--smart-case` | case rule `smart` |
   | `-u`, `--no-ignore` | ignore files are not used |
   | `-uu` | `-u` and `-.` |
   | `-.`, `--hidden` | hidden files are searched |
   | `--no-hidden` | hidden files are not searched |

   Of several case options the last counts. An option whose value is
   still missing at the end of the input is ignored: it is being typed.
   So is a last word that is the start of an option's spelling (`--hid`).
   Anything else that starts with `-` is an error, "Unknown option OPT;
   see the README for the options"; a word that is not an option and
   not a value is an error, "Not an option: WORD".
5. Defaults, as for `quarry-grep`: terms are Rust regexps, the case
   rule is `quarry-grep-case`, hidden files follow
   `quarry-include-hidden`, ignore files are used. `before` and `after`
   are 0.

`quarry-consult-grep-quote` (STRING) returns STRING as input that
searches for it literally: quoted for the Rust regexp engine
(`quarry-grep--regexp-quote`), spaces as `\ `, a leading `!` as `\!`,
and the separator or initial character of the current
`consult-async-split-style` written as `\xNN`, so that it does not end
the search part. It is public, for initial input from Lisp (a region,
an isearch string).

### The async step

`quarry-consult-grep--async` (DIR) returns a step for
`consult--async-pipeline`, built like `quarry-consult--async` (ADR 0008)
but on a stream.

- A new input string: cancel the running call (`emrs-cancel`, with the
  serial number advanced first, so its `:on-end` is ignored), parse the
  input, and start `emrs-call-stream` on the shared instance
  (`quarry-grep--ensure-instance`) with `quarry-grep--request` of the
  parsed search. For the request `quarry-grep-max-lines` is bound to
  `quarry-consult-grep-max-lines`.
- A batch: its file items become candidates and go to the sink. Before
  the first batch of a search the sink is flushed, so the candidates of
  the previous input stay until new ones arrive.
- The end: `done` without any batch flushes; the indicator becomes
  `finished`. `failed` flushes, sets the indicator to `failed` and shows
  the message. `cancelled` does nothing.
- A parse result of nil flushes and shows nothing. A parse error is
  shown like a failed search, without asking the service.
- `cancel` and `destroy` cancel the call and forget the input, as in the
  file finder's step.
- The note: errors, and "first N hits" when the summary says
  `:truncated`, are shown by an overlay at the end of the minibuffer
  input (an `after-string` in brackets; face `error`, or `shadow` for
  the truncation). It is replaced with each new input and removed when
  the prompt ends. Of a message with several lines the last one that is
  not empty is shown: the regexp engine names the mistake there.
  `message` is not used: it hides the input while typing.

A candidate, one per kept line (ADR 0018):

- the string `PATH:LINE:TEXT`, PATH relative to DIR;
- `face` `consult-file` and the property `consult--prefix-group` (the
  path, one string shared by the lines of a file) on PATH;
- `face` `consult-line-number` on LINE;
- `consult-highlight-match` on the item's `:spans`, and the face list
  `(quarry-grep-match-secondary consult-grep-context)` on its
  `:secondary` when `quarry-grep-highlight-include-filters` is non-nil
  (ADR 0018: consult would otherwise count them as matches).

### The commands

- `quarry-consult-grep` (&optional DIR INITIAL): search DIR, by default
  `default-directory`. Interactively with a prefix argument, ask for the
  directory.
- `quarry-consult-grep-project` (&optional DIR INITIAL): search the
  root of the current project, or `default-directory` outside a project
  (`quarry-grep--project-root`). Interactively with a prefix argument,
  choose a project first (`project-prompt-project-dir`). DIR from Lisp
  is searched as given.
- INITIAL is the initial input. Interactively it is the active region
  through `quarry-consult-grep-quote`, else nothing; the symbol at point
  is offered as future history (`M-n`).

Both, before the prompt: check that consult has the functions used
(else a `user-error` that names consult), check the directory with
`quarry-grep--check-directory` (remote: the existing `user-error`), and
call `quarry-grep--type-list`, which starts the instance and reports a
missing module.

The prompt is `consult--read` with `default-directory` bound to the
directory, over the pipeline `consult--async-split`,
`consult--async-min-input`, `consult--async-throttle` (with the two
options below), the step, `consult--async-indicator`,
`consult--async-refresh`; with `:async-wrap #'identity`, `:category
'consult-grep`, `:group #'consult--prefix-group`, `:state
(consult--grep-state)`, `:lookup #'consult--lookup-member`,
`:require-match t`, `:sort nil`, `:history '(:input
quarry-consult-grep-history)`, `:keymap quarry-consult-grep-map` and the
prompt text `Grep in DIR: ` with the directory abbreviated. `RET` visits
the hit.

Options (group `quarry`): `quarry-consult-grep-max-lines` (1000),
`quarry-consult-grep-input-debounce` (0.05) and
`quarry-consult-grep-input-throttle` (0.1). The minimum input length is
consult's `consult-async-min-input`.

The file requires `quarry-grep`, `emrs` and `project`, not `quarry.el`,
and loads and byte-compiles without consult.

### Hand-over to the result buffer

`quarry-consult-grep-map` binds `C-c C-o` to
`quarry-consult-grep-to-buffer`. The command

1. takes the minibuffer's contents and splits them with the function of
   the current style in `consult-async-split-styles-alist`, so that it
   does not depend on what the step last received;
2. parses the search part; an error or nothing to search is a
   `user-error`, and the prompt stays open;
3. leaves the minibuffer and runs the search with
   `quarry-grep--start-search`: the terms are its filters, the options
   its file restriction, case rule and switches; context lines come
   from `quarry-grep-context-before` and `-after` as for `quarry-grep`;
   the cap is `quarry-grep-max-lines`;
4. says in the echo area when a filter part (after the second
   separator) was not carried over.

The check that the result buffer is not being edited
(`quarry-grep--check-result-buffer`) is made in step 2.

## Error handling

| Situation | What happens |
|---|---|
| consult missing or without the functions used | `user-error` before the prompt |
| Module missing or older than the grep service | the existing `user-error`s of `quarry-grep`, before the prompt |
| Remote or missing directory | the existing `user-error`s, before the prompt |
| Invalid regexp, unknown file type, invalid glob (service errors) | no candidates, indicator `failed`, the message in the note; the next input searches again |
| Unknown option, a stray word after ` -- `, two `-t` | the same, without a request |
| Input being typed (`!`, `-t` without value, the start of an option, a backslash at the end, no include term) | no error; nothing or the complete part is searched |
| The instance dies during the prompt | the call fails: note and indicator as above; the next input starts a new instance |
| Hit cap reached | candidates up to the cap, the note "first N hits" |
| Hand-over while the result buffer is edited with wgrep | `user-error`, the prompt stays |
| A module from before this change gets a glob with `/` | the old service error in the note or the status line; rebuild the module |

## Testing

`cargo test`: globs with `/`, `**` and `!`; an excluding glob that
matches a directory keeps the walk out of it; including and excluding
globs together, the last match deciding; a file type with globs; an
ignored file and, with `:hidden nil`, a hidden file that a glob matches
stay out; the two errors; the globs that the existing tests use give the
same files as before.

`tests/run-ert.sh`, new file `tests/quarry-consult-grep-tests.el`,
loaded by the script with the others:

- Parser, without consult or the module: every row of the option table
  with both spellings, attached values, the cut at ` -- `, `\ `, `!`,
  `\!`, the incomplete inputs, each error message, the defaults from
  the options, and `quarry-consult-grep-quote` round trips (the quoted
  string parses to one literal-equivalent term).
- Step, with a recording stand-in for `emrs-call-stream` and a recording
  sink, without consult: flush before the first batch only, candidates
  with the faces and properties above, a superseded search's batch and
  end ignored, the cap bound in the request, the note for a failure and
  for `:truncated`, `cancel` and `destroy`.
- With consult (skipped without it): a candidate made by the step gives
  the right file, line and column through `consult--grep-position`; the
  command end to end on a generated tree with the real module (input,
  candidates, `RET` visits the line); the hand-over leaves a
  `*quarry-grep*` buffer whose search equals the parsed one.
- In `tests/quarry-grep-tests.el`: the file restriction rule (type,
  globs, both, two types), the request for each, and `f` with a path
  glob and an excluding glob against the real module.

Manual, in the author's Doom setup: typing feel against
`+default/search-project` on a large tree; preview while moving through
candidates; `embark-export` (`C-c C-;`) and `C-c C-e` on the candidates;
`C-c C-o` with terms, `!` terms and options; the note for an invalid
regexp while typing, in vertico; a region as initial input that holds
`#` and spaces. consult older than 3.7 is not tested.

## Deviations

Found while implementing, in the review (2026-10-12) and in first use
(2026-10-13). Where this list and the sections above differ, the list
says what was built.

- Several file types, as alternatives (asked for by the author after
  first use): the request field is `:file-types`, a list; the search
  slot is `types`; `-t` may be given any number of times and the files
  prompt takes any number of type names. The errors "Give one file
  type; ..." and "Give one file type with -t" do not exist. A file
  must be of one of the types and pass the globs.
- The search value has the slots `types` and `globs` in place of
  `files`; the first draft kept one slot with mixed words, in which an
  unknown `-t` name would have been read as a glob.
- Secondary matches carry `consult-grep-context` besides their own face
  (ADR 0018), or consult would put point on them.
- The note shows the last line of a message, not the first.
- More input counts as being typed: the start of an option, a backslash
  at the end. `-t=rust` is `-trust`. A tab separates words.
- `cancel` sends `[indicator killed]` when it cancelled a search.
- The service escapes a leading `#` of a glob and refuses a glob that
  names nothing (blank, `!`, `/`), not only the empty one.
- The consult check does not name a minimum version: only 3.7 was run.
